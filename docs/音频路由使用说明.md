# 音频路由使用说明：会议同传、实时字幕与虚拟麦克风

本说明面向腾讯会议、Teams、Zoom、浏览器会议及 OBS 的设备路由。项目通过 Windows 音频端点传递声音，不是给会议软件安装专用插件，也不会自动改变系统默认麦克风。

## 1. 先选择需要的模式

| 需求 | 总览模式 | VB-CABLE 是否需要 |
|---|---|---|
| 只看电脑播放声音的翻译字幕 | 远端字幕 | 不需要 |
| 只看自己讲话的原文 / 翻译字幕 | 麦克风字幕，关闭克隆输出 | 不需要 |
| 自己讲话输出字幕和克隆译音 | 麦克风字幕，启用翻译及克隆输出 | 写入虚拟麦克风时需要 |
| 对方声音变字幕，自己讲话变克隆译音 | 会议同传 | 向会议软件发送译音时需要 |

所有真实识别 / 翻译模式仍需要阿里云服务。仅开启 Web 控制台、做本地设备检测不等于已启动翻译。

## 2. 安装虚拟音频驱动

从 [VB-CABLE 官方网站](https://vb-audio.com/Cable/)获取驱动，解压后以管理员身份运行安装程序，安装完成后重启 Windows。项目的 `install.bat` 只安装 Python 依赖，不安装驱动。

重启后，在 Windows 声音设备和项目“音频设备”页面确认以下两个端点：

| 名称 | 类型 | 数据方向 |
|---|---|---|
| `CABLE Input` | 播放端 | 接收本项目写入的译音 |
| `CABLE Output` | 录音端 | 把上述译音提供给会议软件、OBS 或回录测试 |

设备显示名可能带有 `VB-Audio Virtual Cable` 后缀。以实际枚举为准，不能只因为名字有 Input 就把它当物理麦克风。方向和重启要求依据[官方说明](https://vb-audio.com/Cable/)。

## 3. 在项目中配置四类设备

1. 运行根目录 `start.bat`，进入“音频设备”，刷新设备列表。
2. 麦克风选择实际讲话的物理耳麦 / USB 麦克风；可以保持 Windows 系统默认麦克风仍为物理设备。
3. 媒体捕获选择浏览器 / 会议声音实际播放的物理耳机端点。
4. 克隆译音输出选择 `CABLE Input`，需要推流时启用虚拟输出。
5. 回录设备选择 `CABLE Output`，用于测试对比。
6. 保存，停止旧会话后重新检查设备，再启动需要的模式。

输入被统一为 16 kHz、单声道、PCM16；云端返回的克隆译音为 24 kHz、单声道、PCM16。物理设备的原生格式可能不同，由音频处理链路和设备播放路径适配；不要为了追求低延迟随意修改云端固定格式。

## 4. 腾讯会议 / Teams / Zoom 的设置

以自己说中文、对方说英文为例：

1. 项目“接口与翻译”：麦克风源语言 `zh`、目标语言 `en`；对方源语言 `en` 或自动、目标语言 `zh`。
2. 项目“音色管理”：选择有效的 LiveTranslate 音色；建议固定音色 `never` 策略。
3. 项目设备按上一节设置，先停止正式会话，用测试实验室确认本地路由和实时译音。
4. 会议软件的麦克风选择 `CABLE Output`，扬声器选择同一个物理耳机端点。
5. 返回项目总览，选择“会议同传”并启动。
6. 使用另一台设备 / 另一位参会者确认实际收到的是翻译后的声音，检查数字、专名和尾句。

切勿把项目自己的麦克风也选成 `CABLE Output`，否则可能再次识别译音。切勿把会议扬声器设成 `CABLE Input`，否则远端声音与译音可能混进同一条虚拟路由。

Google Meet 等浏览器会议也需在会议页面中选 `CABLE Output`，并确认该网站获得所需设备权限。不同软件的降噪、自动增益和回声消除效果不同，先按其默认设置试听，再按实际结果调整；这里不宣称所有版本都已通过兼容性认证。

## 5. 媒体捕获为什么可能无声

WASAPI 回环采集的是“选定播放端点上的全部声音”，不是某个会议进程、网页或浏览器标签页。

检查顺序：

1. 确认媒体本身没有静音，Windows 音量混合器中的该程序也有输出。
2. 在媒体播放时执行测试实验室“检测媒体声音”。
3. 确认该程序实际使用的播放端点与项目选择一致；蓝牙耳机可能有多个不同用途的端点。
4. 如果拔插设备、切换系统默认播放端点或改了应用级音量路由，停止会话、刷新设备并重新选择。
5. 捕获已有电平却无字幕，再查云端连接、语言和字幕显示，不要把云端问题误判为设备无声。

推荐始终戴耳机并关闭其他播放器 / 提示音，以免无关声音被翻译。整机端点回环不能保证进程级隔离。

## 6. 字幕、独立演讲与 OBS

- 会议同传中可显示仅对方、仅自己或双方；这只影响显示，不影响两路采集。
- 仅独立演讲时选择“麦克风字幕”。关闭翻译后明确源语言并启用“原文”；开启克隆输出则必须开启翻译。
- “字幕”页面可设置原文 / 译文 / 标签、字号、颜色、背景透明度、紧凑背景、宽度、内边距和上下位置。
- OBS 需要译音时添加 `CABLE Output` 音频输入；需要字幕时捕获悬浮窗或字幕区域。先做短录制确认窗口可见及背景效果。
- 不要同时保留不需要的物理麦克风轨、桌面音频轨和译音轨，避免重复声音。自行添加监听 / 混音时，不要送回媒体捕获端点。

关闭悬浮窗只关闭字幕显示，不停止翻译。关闭浏览器也不代表后台停止。

## 7. 输入电平、噪声与按住说话

先用“平衡模式”，在正常说话距离检测电平；推荐近讲耳麦，麦克风离嘴约 3–8 厘米，再逐步校准应用增益与 VAD。

降低 Windows 输入音量会同时降低自己和环境声音，不能隔离远处讲话。应用噪声门也不能可靠识别“哪一个人才是你”；门限过高会截掉轻声和尾字。

嘈杂环境启用按住说话保护：

1. 在音频设置 / 总览开启保护，设置快捷键，保存后重新启动会话。
2. 让总览页具有焦点，再按住网页按钮或快捷键说话。
3. 说完即可松开；应用继续发送静音，已发送的话音仍会完成翻译和播放。
4. 等尾句结束再停止会话，避免直接关闭服务截断结果。

该快捷键不是系统全局热键。切换到会议窗口、浏览器失焦时，不能假定键盘保护仍按同样方式工作。

按住期间，进入麦克风的其他人声仍可能被识别；保护不是说话人分离或定向降噪，仍需保持近讲和良好的信噪比。

译音 RingBuffer 是容量上限，不是固定排队几秒才播放。遇到吞字应检查溢出和云端突发音频，不应只把缓冲调小。

## 8. 结束与设备占用

- 测试页“停止测试”结束该测试并完成回录收尾。
- 总览“停止程序”结束正式翻译会话，保留 Web 配置服务。
- 根目录 `stop.bat` 关闭整个正式版后台并释放设备。
- 同一麦克风 / CABLE 路由的正式会话、测试实验室和独立测试工具应按顺序运行，避免多路声音混合或设备占用。
- 应用停止后，会议麦克风仍可能是 `CABLE Output`；需要恢复原声会议时，在会议软件中改回物理麦克风。

后续验证见[测试实验室使用](测试实验室使用.md)；音色创建见[声音复刻使用说明](声音复刻使用说明.md)。
