# 测试实验室使用：字幕、克隆译音、虚拟麦克风与延迟

从根目录运行 `start.bat`，进入“测试实验室”。它用于分别验证媒体字幕、云端译音、虚拟设备回录与实际会议可听性；这几个环节不能互相替代。

## 1. 测试前准备

| 测试类型 | 必需条件 | 云调用 / 本地文件 |
|---|---|---|
| 媒体电平或麦克风检测 | Windows 音频设备可用、选择正确 | 本地检测，不等于已调用翻译 |
| VB-CABLE 校准音路由 | 驱动安装重启，Input / Output 方向正确 | 本地路由测试，可生成回录 |
| 媒体字幕 | 百炼密钥、业务空间、权限、正确播放端点 | 真实云调用；原文 / 译文历史用于当前页面观察 |
| 实时克隆译音 | 上述云配置、物理麦克风、有效音色、虚拟路由 | 真实云调用，保存云端译音与虚拟回录 |
| 文件译音 | 独立 CLI 配置、自己的文件、有效音色 | 真实云调用，保存 WAV 与 JSON 摘要 |

开始前停止正式翻译会话，以及其他使用相同端点的独立测试程序。每次测试前确认语言和设备，云端测试会消耗账号额度。

## 2. 字幕效果测试

1. 在“接口与翻译”设置远端源 / 目标语言；例如英文媒体 → 中文。
2. 在“音频设备”选择媒体实际使用的物理播放设备。
3. 打开视频或会议测试音，点击“检测媒体声音”，确认有效电平。
4. 点击“校验字幕链路”，确认配置和设备检查通过。
5. 设置最长测试时间，点击“开始字幕测试”；此测试只启动媒体回环和文本链路，不开启麦克风推流。
6. 同时观察原文、译文、最终字幕历史和媒体 / 云端状态；按需打开测试悬浮窗。
7. 停止测试，检查最后一句是否完整，并关闭不需要的悬浮窗。

建议覆盖短句、长句、数字、缩写、专业术语、静音和少量背景噪声。增量译文可能先出现预测片段，最后应以完成结果判断准确性，不能只截取尚未确认的字幕。

原文有内容、译文没有时，先排查目标语言、同语言跳过和字幕开关；媒体检测无电平时先排查播放端点，详见[音频路由](音频路由使用说明.md)。

## 3. VB-CABLE 本地路由测试

1. 确认项目输出为 `CABLE Input`，回录为 `CABLE Output`。
2. 在克隆译音测试区执行“VB-CABLE 本地路由测试”。
3. 项目发送校准音并回录，检查信号检测、电平和回录文件。
4. 如无声，先解决驱动、端点和输出问题，不要先调云端 VAD。

校准音有声只证明本地虚拟设备可路由，不证明音色、云端翻译或会议对方可听。

## 4. 实时麦克风克隆译音测试

1. 在“音色管理”选择有效的 LiveTranslate 固定音色，推荐 `never` 策略。
2. 设置本地源语言 `zh`、目标语言 `en`，选择物理麦克风。
3. 在测试区检查方向和音色，设置最长测试时间，点击“开始实时测试”。
4. 按正常语速讲话，观察本地原文、译文、云端译音和 CABLE 状态。译音边返回边写入，不需要先录完一整段再上传。
5. 留出一小段停顿，点击“停止实时测试”，等待收尾完成。
6. 在“录音对比与试听”分别播放云端译音和虚拟麦克风回录，比较语言、音色、数字、专名、尾句和静音段。

测试云端录音文件常以 `cloud_clone` 标识，虚拟端点回录以 `virtual_mic` 标识。后者更接近进入会议麦克风的数据，但仍不包含会议软件后续处理。

建议反向再测一次英文 → 中文；注意固定音色必须针对当前翻译模型创建，不能用别的目标模型的 ID。

## 5. 延迟指标的准确含义

总览有远端 / 本地捕获到服务端 VAD、VAD 到首个字幕 / 音频以及写入虚拟输出等状态。这里的服务端 VAD 时间点来自客户端收到相应事件的时间，不是可直接访问的云服务器硬件时钟。

测试实验室按本轮首个有效语音 / 音频信号记录以下指标：

| 页面指标 | 起点 → 终点 | 不能说明什么 |
|---|---|---|
| ① 麦克风 → 云端首块克隆音 | 本地检测到有效讲话 → 收到首块有效云端译音 | 不包含后续虚拟设备和会议传输 |
| ② 云端首块 → CABLE Input | 首块有效云端译音 → 首次有效输出写入 | 不是整个云端生成耗时 |
| ③ 麦克风 → CABLE Input 总延迟 | 有效讲话 → 首次有效输出写入 | 不是对方实际听见的时间 |
| CABLE Input → CABLE Output | 首次有效写入 → 回录首次检测到信号 | 不包含会议编码与对方播放 |
| 麦克风 → 虚拟麦克风总延迟 | 有效讲话 → 回录首次检测到信号 | 仍不是完整会议端到端延迟 |
| 服务端 VAD → 首个翻译字幕 | 接收到起句事件 → 首个翻译字幕事件 | 与麦克风本地电平起点的口径不同 |

“—”“等待语音”“等待推流”表示对应事件还没发生，不代表 0 ms。输出格式错误、同语言跳过音频、没有有效语音、回录无信号等，都可能让后段指标一直为空。

分块时长和缓冲最大容量是配置，不应直接填进这些实测指标。不同口径的起点不能混为同一条链路，也不能把五个不同阶段的数值当成五次重复样本。

### 对比预设与端到端测试

1. 固定设备、音色、语言、测试文案与说话距离，记录网络环境和预设。
2. 每个预设做多轮独立测试，记录每轮首信号指标及是否吞字；单轮首信号并不代表整场每句话的 P95。
3. 如需 P50 / P90 / P95，至少收集足够数量的同口径重复样本，例如每种条件 50 次；同时记录失败 / 无结果次数，不应把失败样本当 0 或无声忽略。
4. 另一端用耳机试听并录制已授权的测试内容，单独评估会议软件的降噪、编码、网络和播放。
5. 用清楚的测试编号和同步可观察标记对齐两端录制，或对齐“讲话 / 原声起点”与“译音起点”；跨机器直接相减未同步的时钟不可靠。

先以平衡模式建立基线，再比较清晰优先与低延迟。没有经过真实采样的数字不能称为已达标性能。

## 6. 结果判断与故障定位

| 云端译音 | 虚拟回录 | 检查方向 |
|---|---|---|
| 有声 | 有声 | 云生成与本地路由可用，继续会议另一端试听 |
| 有声 | 无声 | 输出开关、Input / Output 方向、格式、驱动重启、回录电平 |
| 无声 | 无声 | 麦克风电平、云连接、源 / 目标语言、同语言跳过、音色、VAD |
| 无声 | 有其他声音 | 其他程序混音、Windows 监听、OBS 或错误端点 |
| 文件很长但全程无声 | 没有有效信号 | 时长不代表成功；检查峰值 / 信号状态并按无声失败处理 |
| 字幕正确但声音偶发回到源语言 | 译音不符合目标语言 | 核对源语言、目标语言保护和云端事件；保留脱敏问题信息，不公开原始载荷 |

“写入成功”和“对方听到”不同。会议麦克风选择错误、会议端静音或降噪截断，可能发生在本地回录已经成功之后。

## 7. 试听、删除与结束

测试音频位于 `data/runtime/test_audio/`。停止测试后，使用页面刷新、逐个删除或“删除全部测试音频”。不要在仍写入的录音上执行清理。

页面“停止测试”只结束测试；总览“停止程序”结束正式会话；根目录 `stop.bat` 关闭整个正式版后台。关闭标签页不会可靠释放后台设备。

记录音频与摘要均为私人数据。缺陷描述可包含模型名、错误分类、脱敏参数与时间指标，但不要附 API Key、完整载荷、未经授权的会议录音或完整业务字幕。

## 8. 自动化回归

从项目根目录执行：

```powershell
.\run-tests.bat
```

或在 PowerShell / CMD 使用统一脚本：

```bat
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\manage.ps1 -Action test
```

本地 Mock 与单元 / 集成测试覆盖配置、音频转换、队列、云端事件、页面契约、音色管理和测试引擎。它们不替代驱动、实际云账号和真实会议端验收。

相关说明：[根 README](../README.md)、[音频路由](音频路由使用说明.md)、[声音复刻](声音复刻使用说明.md)。
